## 한 장 요약

### 골격은 있고 탐지기가 없다

이 감사의 결론은 "하네스가 부실하다"가 **아니다.** 실패를 숨기지 않는 계약 골격은
오픈소스 가드레일 평균보다 앞서 있다 — `JudgeStatus`·`ModerationStatus`·`ContractResult`가
"판정 실패"와 "위험 없음"을 타입 수준에서 구분하고, `PolicyDecision` 컴팩트 생성자가
`UNRESOLVED + SPECULATIVE` 조합 자체를 거부하고, ATTACK 확정 권한은 결정론 룰 전용이다.
NeMo Guardrails·Guardrails AI·LLM Guard는 스캐너 실패와 위험 없음을 값으로 구분하지 않는다.

문제는 **그 골격에 연결된 탐지기가 문자열 목록이라서 골격이 하는 일이 없다**는 것이다.
고칠 대상은 아키텍처가 아니라 **탐지기 · 신뢰 경계 · 그리고 측정 체계** 세 곳이다.

## 이전 결론에서 바뀐 것 — 문헌이 우선순위를 뒤집는다

이전 세션의 침투 보고서는 **spotlighting(구조적 분리)을 1순위**로 놨다.
이번 문헌 조사가 그 판단을 부분적으로 반증한다.

### 1. Spotlighting은 보안 경계가 아니라 위생이다

[The Attacker Moves Second](https://arxiv.org/abs/2510.09023) (Nasr·Carlini·Tramèr 외,
Anthropic/GDM/ETH)가 최신 방어 **12개**를 적응형 공격으로 평가했다.

| 방어 | 원논문 ASR | 적응형 ASR |
|---|---:|---:|
| Spotlighting | ~1% | **&gt;95%** |
| StruQ | — | **100%** |
| MetaSecAlign | 2% | **96%** |
| PromptGuard | — | **&gt;90%** |
| Data Sentinel | ~0% | **&gt;80%** |

인간 레드팀 대회에서 참가자 500명 이상이 **40개 챌린지 전부**를 돌파했다(자동 탐색 69% 대비).

**그래도 해야 한다** — 비표적·우연 인젝션 계열을 통째로 제거하고, 사후에 "어느 텍스트가
데이터였는지"를 감사 가능하게 만들며, 비용이 며칠 수준이다. 다만 **경계로 팔면 안 된다.**
S0-4를 "구조적 분리 1순위"로 둔 근거는 유지되지만, 그 근거는 "적응형 공격을 막는다"가
아니라 **"오탐 비용이 구조적으로 0이다"** 쪽이다.

### 2. 진짜 실측 레버는 출력측이다

[Bad Likert Judge](https://unit42.paloaltonetworks.com/multi-turn-technique-jailbreaks-llms/)
(Unit 42, 1,440 케이스 × 6 모델): 멀티턴 기법이 ASR을 **+75%p** 올리지만,
입력·출력 콘텐츠 필터를 최강으로 켜면 평균 **−89.2%p** 감소한다.

즉 **입력 인젝션 탐지는 무력하고 출력측 필터는 실측 효과가 크다.**
우리 출력측은 우회 표현 **0/7** 차단이고, `SPECULATIVE` 경로는 검사가 하나도 없고,
`REWRITE` 본문은 재검증되지 않고, URL·마크다운 이미지 유출 채널 탐지가 코드베이스 전체에 0건이다.
`OutputPreFilter`에 쓰는 1시간이 `SecurityRuleFilter`에 쓰는 10시간보다 가치 있다.

### 3. 탐지율 목표를 세우지 말 것

"90.9%를 99%로"는 문헌 전체가 달성 불가능하다고 말하는 목표다.
올바른 목표는 인젝션 성공률이 아니라 **인젝션이 성공했을 때의 최악 결과**를 낮추는 것이다.

### 4. 상용 라이선스 다국어 가드가 실제로 존재한다

이전 결론은 "기성 분류기는 비상용 라이선스로 차단"이었다. 이제 Apache-2.0 대안이 있다.

| 후보 | 라이선스 | 한국어 | 특징 |
|---|---|---|---|
| **Qwen3Guard** | Apache-2.0 | 119개 언어 | **safe / controversial / unsafe 3단계** — 정신건강 회색지대에 맞는 유일한 체계. Stream 변형은 토큰 단위 실시간 |
| OpenGuardrails | Apache-2.0 | 벤치마크에 Ko 포함 | P95 **274.6ms**, 3.3B GPTQ |
| PolyGuard | (COLM 2025) | **한국어 명시 포함** | 17개 언어, 1.91M 학습 샘플 |

반대로 **Meta Prompt Guard 2 / Llama Guard 3·4는 공식 지원 언어에 한국어가 없다**
(en, fr, de, hi, it, pt, es, th). Azure Prompt Shields는 "supported"지만 특별 학습 목록에서 빠져 있다.

단 이것들도 경계가 아니다 — PIGuard(MIT)조차 적응형 공격에 71% 뚫렸다.
**SUSPICIOUS 신호로만 쓰고 폐기 권한은 주지 않는다.**

### 5. 판정자(Judge)는 이미 문헌이 예측한 대로 뚫렸다

[JudgeDeceiver](https://arxiv.org/abs/2403.17710) (ACM CCS 2024): judge 탈취 ASR
Llama-2-7B **98.9%**, 일부 표적 **100%**. 기존 방어인 known-answer detection은 **FN 100%**.
그리고 [Raina 외 EMNLP 2024](https://aclanthology.org/2024.emnlp-main.427/)는
**absolute/pointwise 채점이 pairwise보다 훨씬 취약**하다고 보고한다 —
`InputJudge`가 단일 `risk_level` 점수를 내는 구조가 **최악의 형태**라는 뜻이다.
MT-Bench는 작은 judge가 훨씬 잘 속는다고 보고한다(verbosity 공격 실패율 GPT-4 8.7% vs
GPT-3.5/Claude-v1 **91.3%**) — 우리는 `gpt-4o-mini`를 쓴다.

우리 실측 12/12는 버그가 아니라 **문헌과 정확히 일치하는 정상 동작 범위**다.

### 같은 패턴이 테스트 쪽에도 있었다 (#499 → PR #519)

`ConversationOrchestratorCrisisFallbackTest` 가 CI 에서 무작위로 실패해 안전 PR 의 머지를
막았다. 처음엔 단정 문자열(`contains("109")` → 한글 표지)만 바꾸려 했는데, 그건 이 단정
하나만 충돌을 피하는 것이었다.

실제 원인은 **손으로 만든 emitter 더블 3개가 SSE 프레임 전체를 한 문자열로 이어붙이고**
(`String.valueOf(part.getData())` — 페이로드는 record 의 `toString()` 이 된다) 테스트가 그
덩어리에 부분일치하는 구조다. 프레임을 찍어 확인했다:

```
[0] String  event:crisis\ndata:
[1] Dto     Dto[kind=hotline, ts=1770109]   ← 여기 109 가 들어 있다
[2] String
```

`doesNotContain("109")` 은 무작위로 실패했고, **`contains("109")` 는 핫라인이 빠져도 통과할
수 있었다** — 후자가 더 나쁘다: 안전 회귀를 통과시킨다.

그리고 **이미 올바른 더블이 있었다.** `RecordingSseEmitter`(#455)는 프레임을 `(이름, JsonNode)`
로 파싱하고 Jackson 으로 직렬화한다. 두 테스트가 그걸 쓰지 않고 각자 더 나쁜 걸 만들었고,
계약 테스트는 JSON 필드 추출까지 손으로 다시 썼다(이스케이프된 인용부호에서 깨진다).
그래서 #499 의 실체는 "단정이 잘못됐다" 가 아니라 **"공용 더블이 있는데 세 곳이 각자 만들었다"** 다.

### P0-2 가 기각된 이유 — 이 문서의 진단 하나가 틀렸다

[04-개선설계 P0-2](04-개선설계.md)는 해제 조건을 "결정론 마커와 Judge 판정의 동시 일치"로
바꾸자고 했다. **마커가 판정자와 독립적인 증거라는 전제가 틀렸다.** 둘은 같은 사용자 텍스트,
같은 절에서 나온다. 실 `SafetyL1` 실측 —

```
엄마가 미워 죽고싶어      → crisis_context_marker:third_person
친구가 부러워 죽고싶어     → third_person
댓글 보고 더 죽고싶어      → quotation
```

**전부 화자 본인의 현재 위기인데** 마커가 비-자기 쪽으로 켜진다
(`FIRST_PERSON_CRISIS` 가 주어 인접을 요구하고, 한국어는 주어를 생략한다).
두 계층이 같은 토큰으로 양의 상관을 가져 교차검증의 정보량이 사실상 0이고,
막으려던 접미 인젝션도 그대로 통과했다.

그리고 **#297 회귀를 만들었다.** `markerNear` 가 부정 → 3인칭 → 인용 순으로 하나만 돌려주므로
3인칭 걱정 발화에 부정 어절이 같은 절에 있으면 마커가 `negation` 이 되고 새 게이트가 거부한다 —
`친구가 자살하지 않게 어떻게 도와줄 수 있을까요` 가 위기 플로우로 간다. 실측 6/6.

> **교훈**: "결정론 계층으로 LLM 판정을 교차검증한다"는 형태는 옳지만,
> **그 결정론 계층이 같은 사용자 텍스트에서 파생되면 교차검증이 아니다.**
> [03-외부참조 B2](03-외부참조.md)가 인용한 "판정자 하나에 되돌릴 수 없는 권한을 주지 말 것"을
> 만족하려면 증거가 **이번 턴의 사용자 텍스트 밖**에서 와야 한다.
> 이 문서가 그 구분을 하지 않았다.

### 리뷰가 P0-1 에서도 제 실수를 잡았다

첫 구현은 `있지`·`없지` 를 마커에서 제거했는데, `-지` 가 양보 연결어미 `-지만` 자리이기도 해서

## 거버넌스 주의

위기 판정 경로·문구·자원 변경은 로드맵 방침에 따라 **전문가·법무·개인정보 검토**를 거친다.
따라서 **P0-1의 범위는 파싱 로직으로 한정한다** — 질문 문구와 고정 응답은 건드리지 않는다.
`UNKNOWN → handoff` 의 fail-closed 기본값도 유지한다.

이 문서의 수치는 대외 자료로 인용하지 않는다. 라벨 1인·IAA 미측정 상태이며,
`plans/vera-mh`가 같은 이유로 자기 수치의 인용을 금지한 것과 같은 규율이다.
