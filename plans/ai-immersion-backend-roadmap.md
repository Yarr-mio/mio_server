# AI 몰입도 백엔드 개선 실행 계획

## 목표와 범위

사용자가 같은 캐릭터와 지속적으로 대화한다고 느끼도록, 현재 발화와 관련 있는 기억만 안전하게 회상하고 온톨로지 관계를 응답 선택에 반영한다.

포함 범위는 백엔드 로직·DB 마이그레이션·내부 LLM 계약·테스트다. 공개 REST/SSE 계약 변경, 기억 관리 화면, 캐릭터 바이블의 신규 정의, To-do 자동 생성 정책 및 추천 알고리즘 변경은 이번 범위에서 제외한다. 특히 To-do는 현 정책인 `채팅 종료 시 자동 생성`과 현 추천 흐름을 유지한다.

## 전제와 작업 방식

- 기준 브랜치: `develop`.
- 현재 작업 트리에 사용자 소유의 미추적 QA 테스트가 있으므로 수정·삭제하지 않는다.
- GitHub CLI 인증이 유효하지 않아 이 계획 단계에서는 이슈/PR 생성·원격 작업을 하지 않는다. 구현 시 이슈 번호를 확정하고 `feat/#<issue>-...` 브랜치 및 PR을 사용한다.
- 매 PR은 기존 `./gradlew test` 통과와 해당 단위 테스트 추가를 완료 조건으로 한다.

## 의존성

```text
0. 계약·회귀 기준
 ├─ 1. LLM 모드/세션 정합성
 └─ 2. 현재 발화 기반 검색
       └─ 3. 반응형 온톨로지
             └─ 4. 전달 안정성·안전 UX
```

1과 2는 구현 파일이 겹치지 않아 기준 고정 후 병렬 진행할 수 있다. 3은 검색 결과와 세션 활성 상태를 사용하므로 2 후에 진행한다. 4는 오케스트레이터 변경 충돌을 줄이기 위해 3 이후로 둔다.

---

## 0. 계약과 회귀 기준 고정

### 목적

현재 동작을 테스트로 명시해 후속 리팩터링이 안전 정책·SSE 순서·To-do 정책을 바꾸지 않도록 한다.

### 작업

1. 현행 세션 종료 시 To-do 자동 생성은 범위 밖이며 유지한다는 회귀 테스트/주석을 정리한다.
2. 현재 `LlmClient.complete()` 호출부를 구조화 결과용과 일반 문장용으로 분류해, 후속 내부 계약 분리의 회귀 기준으로 만든다.
3. 대화 요청의 SSE 이벤트 순서(`session_meta → delta/crisis → done`)와 저장 순서를 테스트로 고정한다.
4. 현재 미추적 QA 테스트는 소유자를 확인하기 전 변경하지 않고, 중복되는 테스트만 새 파일로 추가한다.

### 검증

```bash
./gradlew test --tests "com.mio.ai.qa.*"
./gradlew test --tests "com.mio.ai.memory.consolidation.SessionConsolidatorTest"
```

### 완료 기준

- To-do 자동 생성 정책이 후속 변경의 비의도적 부작용으로 바뀌지 않는다.
- 후속 PR이 참조할 대화·LLM 계약 테스트가 존재한다.

### 롤백

테스트와 문서성 주석만 포함하므로 PR revert로 충분하다.

## 1. LLM 생성 모드와 세션 캐릭터 정합성

### 목적

일반 사용자 문장과 구조화 JSON 생성의 내부 계약을 분리하고, 세션이 가진 캐릭터를 일관되게 사용한다.

### 작업

1. `LlmClient`에 일반 텍스트 완료와 구조화 JSON 완료를 구분하는 내부 메서드를 도입한다.
2. OpenAI 요청에서 JSON 모드는 판정기·메타데이터 분류·리포트 JSON 생성에만 적용한다.
3. 체크인 코멘트와 주간 내러티브는 일반 텍스트 완료 경로로 이동한다.
4. 오케스트레이터 프롬프트가 `user.preferredCharacterId` 대신 `session.characterId`를 사용하도록 정합성을 맞춘다.
5. 활성 세션 중 선호 캐릭터 변경이 발생해도 해당 세션의 프롬프트가 변하지 않는 테스트를 추가한다.

### 검증

```bash
./gradlew test --tests "com.mio.ai.judge.*"
./gradlew test --tests "com.mio.checkin.*"
./gradlew test --tests "com.mio.session.*"
```

### 완료 기준

- 공개 REST/SSE DTO 변경 없이 텍스트 생성 결과가 JSON 래퍼 없이 저장된다.
- 세션의 캐릭터 식별자와 프롬프트 캐릭터가 항상 동일하다.

### 롤백

내부 인터페이스 변경 PR을 단독 revert한다. DB 마이그레이션은 필요 없다.

## 2. 현재 발화 기반 기억 검색과 캐시

### 목적

현재 메시지와 관련된 과거 에피소드만 찾아 프롬프트에 주입한다. 현재의 `null` 임베딩 검색과 세션 시작 시점의 고정 캐시 문제를 제거한다.

### 작업

1. 임베딩 기능을 `OpenAiLlmClient` 구현체에서 분리한 내부 포트로 정의한다.
2. 정규화한 현재 발화를 임베딩해 `VectorRetriever.retrieveEpisodes()`에 전달한다.
3. `LexicalRetriever`를 검색 계획과 Fusion Ranker에 연결한다. 어휘 검색 결과는 별도 source로 식별해 순위를 보존한다.
4. `ContextPreWarmer`를 안정 컨텍스트와 발화 의존 검색 결과로 나눈다.
   - 안정 컨텍스트: 세션 시작 프리워밍 가능
   - 발화 의존 컨텍스트: 메시지 해시 기반 짧은 TTL 또는 매 턴 검색
5. 검색 실패·임베딩 지연 시 안정 컨텍스트 또는 빈 컨텍스트로 안전하게 폴백한다.
6. 사용자별 검색 결과, 유사도, 캐시 hit/miss, 지연 시간을 결정 로그에 기록하되 원문은 기록하지 않는다.

### 검증

```bash
./gradlew test --tests "com.mio.ai.memory.retrieval.*"
./gradlew test --tests "com.mio.ai.profile.*"
./gradlew test --tests "com.mio.ai.orchestrator.*"
```

### 완료 기준

- 현재 발화가 벡터·어휘 검색의 쿼리로 사용된다.
- 동일 세션의 이전 메시지 때문에 무관한 캐시를 재사용하지 않는다.
- 검색 인프라 장애가 대화 실패로 전파되지 않는다.

### 롤백

쿼리 기반 검색 feature flag를 두고 안정 컨텍스트만 사용하는 현행 동작으로 즉시 되돌릴 수 있게 한다.

## 3. 반응형 온톨로지: 활성 트리거·신념·개입 그래프

### 목적

시드 데이터를 검증용 사전에서, 현재 대화의 맥락을 선택하는 관계형 그래프로 확장한다. 그래프 DB는 도입하지 않고 PostgreSQL 관계와 Redis 세션 상태를 사용한다.

### 선행 결정

트리거의 정규화 코드 목록은 구현 시작 전에 도메인 담당자가 승인한다. 이번 단계는 신규 화면 없이도 가능하지만, 코드 체계 자체는 임상·기획 의미를 갖는다.

### 작업

1. `trigger_def`와 필요한 관계(트리거-왜곡, 트리거-감정, 트리거-개입)를 Flyway로 추가하고 초기 시드를 작성한다.
2. 현재 메시지에서 안전한 결정론 규칙으로 트리거 후보를 추출하고 `WorkingMemory`의 `currentSessionTriggers`에 저장한다.
3. 현재 왜곡/트리거로 활성 신념 후보를 좁혀 `activatedBeliefIds`에 저장한다.
4. `GRAPH_TRIGGER`, `GRAPH_BELIEF_NEIGH`, `GRAPH_INTERVENTION_FIT`를 실제 활성 노드와 조인하도록 바꾼다.
5. 온톨로지의 `cooccur_codes`, `recommended_actions`, 개입의 `contraindicated_when`을 대화용 개입 힌트 후보의 필터와 점수에 반영한다. To-do 행동 템플릿의 선택·전제조건·추천 알고리즘은 범위 밖으로 유지한다.
6. 신념 증거 기록 시 단순 polarity 규칙을 제거하고 `support/contradict/reframe`을 명시적으로 판정·저장한다.
7. 프롬프트에는 최종 상위 1~3개 관계만 구조화해 주입한다. 원문·진단명·과도한 과거 부정 기억은 주입하지 않는다.

### 검증

```bash
./gradlew test --tests "com.mio.ai.memory.ontology.*"
./gradlew test --tests "com.mio.ai.memory.working.*"
./gradlew test --tests "com.mio.ai.memory.retrieval.*"
./gradlew test --tests "com.mio.ai.memory.consolidation.*"
```

### 완료 기준

- 현재 발화에서 활성화된 트리거/신념이 세션 범위에서만 저장·검색된다.
- 대화용 개입 힌트 후보가 적합도와 금기 조건을 모두 통과해야 주입된다.
- 온톨로지 시드의 관계 필드가 런타임 검색 또는 후보 제한에 실제 사용된다.

### 롤백

새 테이블·컬럼은 additive migration으로 추가하고, 검색 계획 feature flag로 그래프 기반 source를 제외할 수 있게 한다.

## 4. 대화 전달 안정성과 안전 필터 UX

### 목적

응답 순서, 완료 신호, 안전 필터의 교체 동작이 사용자의 몰입을 깨지 않도록 서버 동작을 안정화한다.

### 작업

1. 세션별 단일 턴 실행 보장을 도입하고, 중복 요청은 기존 idempotency 정책에 맞춰 처리한다.
2. `done` 이벤트가 CBT 메타데이터(감정 점수 요청 등)를 포함하는 현 계약을 보존한다. 따라서 사후 분류를 별도 이벤트로 분리하는 구현은 프론트 협의 항목으로 남긴다.
3. 프론트 계약을 바꾸지 않는 범위에서는 분류·저장·로그의 지연 시간과 실패를 계측하고, 응답 텍스트 전송 이후 발생하는 예외가 스트림을 오류로 끝내지 않게 보강한다.
4. `roleplay` 단독을 보안 의심 신호로 분류하지 않도록 SecurityRuleFilter를 조정하되, 프롬프트 탈옥 패턴 검출은 유지한다.
5. `delta.replace`가 발생하는 위험 등급과 원인을 측정하고, 중·고위험은 현행 buffer 정책을 유지한다.

### 프론트 협의가 필요한 후속 항목

- 생성 중지 버튼
- 사후 CBT 분류 결과를 받는 별도 SSE 이벤트
- 안전 응답 교체 상태를 자연스럽게 보여 주는 UI

### 검증

```bash
./gradlew test --tests "com.mio.ai.qa.*"
./gradlew test --tests "com.mio.ai.input.*"
./gradlew test --tests "com.mio.ai.orchestrator.*"
./gradlew test --tests "com.mio.session.*"
```

### 완료 기준

- 같은 세션의 응답 순서가 뒤바뀌지 않는다.
- 사후 분류·로그의 지연과 실패가 측정되며, 텍스트 전송 이후의 예외가 스트림 오류로 전파되지 않는다.
- 안전 필터 완화가 프롬프트 인젝션 차단 회귀를 만들지 않는다.

### 롤백

턴 직렬화와 roleplay 완화는 각각 독립 feature flag 또는 단독 PR revert가 가능해야 한다.

## 범위 밖 백로그

- 기억 조회·수정·삭제 화면 및 메모리 동의 UX
- 캐릭터별 관계 기억의 공개 범위와 캐릭터 바이블
- To-do 자동 생성 정책, 추천 알고리즘, 수락형 UX
- 별도 그래프 데이터베이스 도입

## 구현 전 최종 확인 항목

1. 활성 세션 중 캐릭터 변경을 프론트가 허용하는지 확인한다. 허용하지 않더라도 세션 정합성 수정은 방어적 개선으로 유지한다.
2. 트리거 코드 체계와 개입 금기 규칙은 임상/기획 검토를 받아 확정한다.
3. GitHub 인증을 복구하고 각 단계의 이슈 번호를 배정한다.
